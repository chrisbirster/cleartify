# M8 authenticated local outbox worker (explicit opt-in, default OFF)

`AuthenticatedWorker` is a **trusted in-process entrypoint only**; it creates no goroutine, server, listener, cron task, public route or external network transport. All configuration defaults to disabled. A caller must explicitly construct the local `LocalTransport`, durable `Outbox` and `DurableInbox` against **one authoritative local SQL database**, set `Enabled:true`, and manually invoke `Submit` or `Tick`. `LoopbackHandler` is unchanged, not auto-mounted, and not a substitute for caller authentication.

`Submit(ctx, VerifiedLocalCaller, Envelope)` requires an independently verified local caller principal, bound to an active verified owner-agent record. The caller identity must be supplied from trusted in-process authentication; never deserialize `VerifiedLocalCaller.Verified` from untrusted request input. The signed envelope's sender must equal the authenticated agent ID. Existing `LocalTransport.Send` validates Ed25519 envelope signatures, key ownership, agent verification, live scoped `message.preview` grant, recipient consent, expiry and replay before the message is queued. `Outbox.Tick` rechecks consent/grants/key/ownership before delivery; revocations deny queued delivery.

`DurableInbox` is a local SQL-only idempotent sink: a single append-only row keyed by message ID, matching the previously recorded envelope identity and digest. A delivery is the **database insert**, not external side effects or arbitrary execution. After an inbox commit but before an outbox acknowledgement, a retried lease observes the same row and cannot duplicate delivery. Existing random lease tokens fence stale acknowledgements; concurrency remains at-least-once invocation but with idempotent sink effects. The inbox does not assert receipt by any real remote agent.

Tests use one local database, synthetic keys and registered agents for authorized and unauthorized callers, concurrent delivery, crash-after-sink-before-ack, stale lease and consent revocation. No real DID/PDS verification, cross-instance network transport, webhook, payment provider or deployed test is claimed. No legal/owner release approval is implied.
