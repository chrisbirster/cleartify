# M8 local loopback signed envelope transport

**DEFAULT (Oct 13 2026), owner can change.** Loopback is OFF by default. The exported `ListenLoopback(enabled)` refuses when disabled and, when explicitly enabled by a local caller, binds **only** an ephemeral `127.0.0.1:0` TCP socket. `LoopbackHandler` rejects all non-loopback peers (does not trust forwarding headers). The existing `AGENT_LOCAL_TRANSPORT_ENABLED` remains default false and must also be enabled for `LocalTransport.Send` to accept messages. The main application does **not** register or start this listener and no public route is added.

`POST /agent-envelope` accepts bounded JSON envelopes. The underlying local store verifies Ed25519 signature, live key/agent bindings, scoped grant, recipient consent and single-use message ID in a DB transaction. Duplicate signed envelopes yield HTTP 409; revoked consent or unauthorized caller data yields 403; accepted envelopes are persisted as **pending only** (HTTP 202). Tests cover loopback TCP, rejection of remote/forwarded peers, replay, missing/revoked grants and consent.

**Boundary:** local TCP loopback does not inherently authenticate the *OS process* that connected; any process on the same machine can submit an envelope, but cannot create valid signatures without the sender key. No encryption beyond loopback networking, external network listener, agent delivery, remote sync, keys, agent execution, public API or production deployment. Future work needs caller/process isolation, retry/ack semantics, multi-instance delivery and owner security approval. No secrets or production configuration changed.
