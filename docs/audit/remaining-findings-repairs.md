## Upgrade and behavior requirements

- Apply the versioned migrations through normal startup after backing up the database. Migration 2 pins legacy request content; migration 3 adds explicit installation publication/digest fields. Downgrading the binary against a newer recorded schema is rejected.
- Historical slug-only or unpinned installations must be explicitly reinstalled/reacknowledged. Existing run requests without a pinned digest cannot be approved. No migration guesses a creator from a slug, deletes a user's records or silently grants authorization. Permissionless guides have the existing self-serve reinstall path; this does not add a general executable-install workflow.
- Pending beta invitations predating the first repair batch still require reissue because they lack an identity snapshot. Invitations issued with a snapshot can now resume an existing activation until its original expiry. The email capability cannot produce a second account or bypass the SMS code, attempt budget, revocation or lock state.
- Blocks prevent authenticated interactions between local identities. They are not a promise that already-public profiles or protocols become secret from an anonymous visitor. Unblocking does not restore removed follow edges; an explicit follow can clear the opt-out.
- Profile setup retains a generated local handle. Reserved-handle transfer and verified celebrity account claims are separate product work. Setup defaults to private; making a profile public is explicit.
- Fake accounting and local messaging remain behind their existing prerequisites. Local messaging requires AgentTransportEnabled, AgentOwnershipEnabled and OAuth in the executable. The owner submission route is `POST /api/me/agents/{id}/messages`; operator routes are `POST /api/admin/agents/{id}/activate` and `POST /api/admin/agents/local-worker/tick`. There is no external-agent delivery, outbound adapter, real payment or arbitrary executor.
- Creator sync errors can occur after a local commit. An identical create/publish/takedown retry recovers the existing result and retries Push without duplicating the version or audit. Conflicting immutable draft payloads still fail. Successful responses require the configured Push callback to succeed; real remote replication has not been exercised.

## Validation boundary

Full uncached Go tests, go vet, the production frontend build and the pinned Go 1.26.1 Docker build have passed locally. Additional final validation is recorded in remediation.md. Browser checks used a disposable local encrypted OAuth-session fixture rather than a real PDS login. No production data, credentials, notification provider, real purchase, remote sync target or external chatbot was used. Temporary fixture sources, browser tabs and servers were removed.

The remaining work is product and deployment acceptance: real hosted-PDS onboarding/revocation, live delivery and restore/replication validation, creator authoring/catalog/configuration/export UI, a coherent social launch experience, and any real-payment or external-agent integration. The original audit's feature inventory is not a list of implemented launch features.
