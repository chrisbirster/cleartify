# Cleartify Docs

Cleartify is a text-first personal assistant. The normal user talks to one contact — **Clear** — while protocols, specialist agents, models, tools, approvals, and long-running jobs stay behind the scenes.

## Product shorthand

- **Product:** Cleartify
- **Assistant/contact:** Clear
- **Catchphrase:** **Clearly.**
- **Core behavior:** ask Clear normally; Clear figures out the machinery.
- **Social idea:** people have profiles that show the protocols they choose to share.
- **First-friend mechanic:** users who opt into Cleartify Social start with Chris as the intentional first friend/follow — an early-social-web wink without forcing social onboarding on everyone.

Examples of the voice:

> “Can you handle this?”  
> **Clearly.**

> “Did I forget anything?”  
> “Two things. I can handle one of them for you.”

## Product principles

1. **One friend, not an org chart.** The user talks to Clear, not a collection of agents.
2. **Outcomes over answers.** A task can remain active while Clear waits, follows up, or runs a protocol.
3. **Text is the primary interface.** The web app is for onboarding, permissions, profiles, protocols, billing, and history.
4. **Protocols are executable playbooks.** They define repeatable ways of accomplishing a goal.
5. **People distribute protocols.** Creator profiles are the human discovery layer for the protocol marketplace.
6. **Private by default.** Personal context, installed protocols, and run activity are not public unless the user explicitly publishes them.
7. **Approval before consequence.** High-impact actions require explicit authority.
8. **The model is replaceable plumbing.** Product value lives in relationship, context, protocols, execution, and trust.
