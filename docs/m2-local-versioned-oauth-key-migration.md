# M2 local OAuth encryption key migration (manual, default OFF)

Existing storage uses `SecretBox`: AES-256-GCM with a random nonce prepended to ciphertext, and associated data bound to `request:<state>` or `session:<DID>:<session ID>`. Its deployed reader has **no key version**. Replacing the configured secret directly makes historic records unreadable, as the existing key rotation test demonstrates.

This PR provides a **separate, local-only** `OAuthKeyring` and `OAuthLocalMigrator`, not automatic production rotation. Ciphertext version 0 is the existing byte layout; versioned ciphertext has a fixed magic header and 32-bit version followed by an unchanged AES-GCM nonce/ciphertext payload. The keyring decodes version 0 and explicitly configured numbered versions; missing/unknown versions and incorrect keys fail closed. Keys are inputs from the trusted local test/operator harness; no key values are emitted, saved in database tables or exposed by an HTTP endpoint.

A trusted local caller must explicitly set `OAuthLocalMigrator.Enabled=true` and call `Migrate(ctx,from,to)` with a **single authoritative local SQL database**, including both `atproto_oauth_requests` and `atproto_oauth_sessions`. All rows must be at `from`; mixed versions cause the operation to fail atomically, not guess. Each row is decrypted using its original associated identity, re-encrypted using the target, and updated with an old-ciphertext comparison inside **one SQL transaction**. An interruption or wrong key rolls the transaction back with no partial ciphertext conversion. Reverse `Migrate(ctx,new,0)` is available only while both keys are retained; original ciphertext bytes differ after rollback because of fresh AEAD nonces, but plaintext remains readable using the existing legacy reader.

**Critical cutover boundary:** Existing `OAuthStore` and `NewSecretBox` are intentionally unchanged and do **not** read newly versioned data. Do not run the migration against a live application or remotely synced database; it requires an owner-reviewed coordinated reader cutover, quiescing writers, durable backup/recovery, key custody and independently verified restore before any production use. This PR performs neither rollout nor production secret rotation, remote Push, OAuth/PDS calls, staging/deploy, legal approval or runtime scheduling. The feature is OFF unless the local caller explicitly opts in.
