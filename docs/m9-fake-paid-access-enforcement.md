# M9 fake-only paid access enforcement — Round 3

**Default OFF:** `FAKE_PAID_ACCESS_ENFORCEMENT_ENABLED=false`. Requires the existing `FAKE_CHECKOUT_ENABLED=true` and OAuth configuration for authenticated buyer checks. No real provider, payment calls, credentials, SDKs or billing.

When enabled, the anonymous public discovery list excludes listed paid protocols and unauthenticated install-manifest previews deny paid listings. Authenticated install requests and the Clear fake-run entrypoint check a fresh *active fake* entitlement for the authenticated social DID against every listed paid publication. Free/unlisted publications are unchanged; the runtime still requires its existing linked Clear/social principals, alpha membership and approved immutable install manifest. Existing paid access-check endpoint verifies current entitlement. A refund removes access. Repeated fake checkout for one buyer/listing returns the active entitlement ID, without a second fake purchase audit; refunded entitlements cannot be silently reactivated. `ReconcileFake` inspects purchase/refund audit correspondence.

**Limitations:** These checks cover currently identified public catalog/manifest, install request, and fake-run entrypoints. New paid access paths must use the same guard. A listing that is withdrawn or re-priced and cross-instance races require further policy/testing. Public catalog hiding is not authenticated purchaser browsing; listing metadata remains subject to public routes outside this implementation. Existing fake-only receipts cannot authorize live paid access. No deployment, legal wording, real money or external calls.
