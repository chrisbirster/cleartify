## Critical interpretation

**Formally done is still only M0, and launch readiness is far below the ~85% local-engineering roll-up.** A green Go/web CI, a fake-only E2E journey, or local encryption/agent signature proof cannot replace a production security review, staging evidence, provider integration or counsel-approved public language. The percentages are **judgment estimates, not measured**; the roll-up is an approximate holistic estimate, not a mathematically weighted calculation.

**Internal approvals versus legal sign-off:** Chris approved the conservative M3 moderation-policy and M7 agent-verification defaults in #73 as **INTERNAL defaults**, **not final legal wording; counsel review pending**. M0 retention defaults likewise do not constitute public legal promises. **No counsel sign-off is claimed.** Fraud/impersonation report thresholds, appeal target times, scopes and agent grant TTLs are documented/internal controls; any policy constants not wired to enforcement must not be portrayed as automated operations.

**No real-provider substitutions:** M2 still needs a public HTTPS origin and disposable Bluesky test account to conduct the real PDS OAuth verification in #75; **neither was supplied and deployment has not been granted**. M9's fake provider is intentionally not a real payment integration and cannot process money. M5's local sandbox interprets only approved declarative operations and provides no OS-level isolation for arbitrary untrusted code. M8 outbox delivery is at-least-once and multi-instance-safe only with the same authoritative transactional SQL database; external agent delivery is not implemented.
