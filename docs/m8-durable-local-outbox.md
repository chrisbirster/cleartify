# M8 durable local outbox (opt-in; internal only)

**Default OFF.** `interop.Outbox{Enabled:false}` has no delivery capability. This is a local/loopback **receiver-facing** outbox for messages already accepted by the signed, consent-checked `LocalTransport.Send`; no remote URLs, real network endpoints, external credentials, production configuration or deploy.

## Local use

Construct `Outbox` explicitly in a local harness with the same SQL database used by `LocalTransport`, `Enabled:true`, a local-only `Sink` (e.g., `NoopDelivery`), `Lease:10*time.Second`, `Backoff:time.Second`, and `MaxAttempts:3`. After the pre-existing transport accepts a signed message, call `Enqueue(ctx,messageID)`. Enqueue is idempotent and requires an already accepted, unexpired pending transport record; it does **not** allow new raw unverified envelopes. Call `Tick(ctx)` from the local harness to claim and attempt one due delivery. There is no auto-started worker, listener, URL, database remote sync or external HTTP service.

SQL outbox rows persist attempts, due times, random lease tokens, lease expiry, last internal error key and state (`pending`, `leased`, `delivered`, `dead`). Claim uses a conditional write in a transaction, allowing multiple workers sharing the **same writable SQL database** to compete without simultaneously owning a live lease. Final state transitions are fenced by token so stale workers cannot commit after a lease takeover. Ordinary delivery errors retry after exponential backoff, up to configured attempt limit (1–10) and a maximum 1h delay. Expired messages, revoked grant/consent/binding and missing verified agent state are terminal dead letters; no automatic replay of dead letters. Only internal error categories are persisted, not exception text or secrets.

Before delivery, the worker re-checks message expiry, signing-key status, verified sender and recipient bindings, live `message.preview` grant and recipient consent; failure is fail-closed. This layer trusts the already verified signed envelope from `LocalTransport.Send`; it does not perform a new signature verification. No untrusted scripts or agent execution are performed. Tests cover missing/disabled enqueue, idempotence, unauthorized dead-letter, leased exclusion, expired-lease takeover and fencing against stale completions. Run `go test -p 1 ./internal/interop`, automatically included in existing CI.

## Operational limits

Delivery is **at least once**, not exactly once. A worker may complete its local sink action then lose its lease or fail to record acknowledgement, so sinks must independently deduplicate by `MessageID`. Expiry and revocation checks are snapshots immediately before delivery; revocation concurrent with sink execution may require additional sink-level coordination. The local delivery callback is in-process, not an OS sandbox. No distributed clock guarantees, remote transport, background scheduler, operator dead-letter replay UI, automatic retention cleanup or production monitoring are provided. Multi-instance safety assumes atomic SQL transactions and a **shared authoritative SQL database**; separate local replica databases without coordinated writes are NOT safe. Feature wiring into the main runtime is intentionally not enabled.
